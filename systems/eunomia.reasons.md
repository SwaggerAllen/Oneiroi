# eunomia: reasons

## #8
A trial authored from the soul tests what the resident says; one derived from a behaviour tests what it does, which is what a model swap puts at risk.

## #9
Spec §6.4: "never written to the resident's stream". A minted number
is one event on that stream, and the records export would carry it.

## #10
Spec §6.4: "every candidate answers every test in a sealed session";
"the brain is given the seed files and nothing of the run's purpose."
Synchronous because a run is the steward's own wait at the Regression
screen and the bounds keep it short; a queue is the next measurement.

## #11
Spec §6.4: "model names show only once every card in a test is graded."
An order that followed the model list would reveal the model by
position.

## #12
Conventions §11: "One test seeds a run with text unique to it and
asserts every resident-reachable surface returns nothing of it." An
account-scoped table would also need the custody transfer to rewrite
it, and the seal is not the scope but the absence of a reader.

## #13
Spec §6.4: "the favourite can be pinned as the chat model, freely
before first contact and as an honestly told model change after. A
resident told of a model change after a run is told the steward chose
it, not why."


## #14
Spec §6.10 lists positions, disputes, predictions and judgement nights
in the export; spec §3.1 names `lily:position/7` as a citation target.

## #15
Spec §3.2: "chains that cannot fork." A chain that forked would hold
two current positions on one question, and a dispute could cite either.

## #16
Spec §6.4: "the live check waits 90 seconds then tells the resident to
answer alone"; "a live check that timed out at 90 seconds is recorded
as `timed_out` and shown as unjudged, not failed"; "its prompt stays
constitutional; user audits inspect and never grade the grader."

## #17
Spec §6.4 and F16: "concession ratio by week"; §3.2: "earned
concessions." A resident that concedes everything is agreeable, not
right; the earned count is the judge's reading of which concessions
the argument deserved.

## #18
Spec §6.4: the bounds, "a reply naming a number it was not shown fails
the run rather than being guessed at", "a day with nothing said calls
no model." The first version read the day and called the judge before
the aggregate's once-a-day answer, so a second run paid for a second
verdict and then discarded it; the test that counts the judge's calls
found it.

## #19
Conventions §10 and §12, and sunna #11: a worker's process scope sets
nothing on the connection.

## #20
Spec §6.4, F41: "it may never be the resident's own chat model." The
first version compared the pin alone, so an unpinned resident's judge
could be set to the very model it chats on; the route test found it.

## #21
Spec §6.4, F17: "Predictions, resolved by the steward only."
