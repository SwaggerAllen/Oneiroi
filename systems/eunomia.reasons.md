# eunomia: reasons

## #8
A trial authored from the soul tests what the resident says; one derived from a behaviour tests what it does, which is what a model swap puts at risk.

## #9
Spec §6.4: "never written to the resident's stream". A minted number
is one event on that stream, and the records export would carry it.

## #10
Spec §6.4 as first written: "every candidate answers every test in a
sealed session"; "the brain is given the seed files and nothing of the
run's purpose." Synchronous at first, because a run is the witness's
own wait at the Regression screen and the bounds keep it short. It is a
job now (#30).

The seed-only trial was replaced on 2026-11-01. The author: "that was a
misfeature, we want retrieval, self is continuous experience so we
aren't testing the resident without their memory, there shouldn't be
the option to run with the face but not the memory, but we don't want
to record anything from the trial, those tools should be mocked so the
resident perceives a normal session." A trial without memory graded a
face: the prompt file and the identity files, which any model can read
aloud, and none of what the resident has kept, promised or become. So
a trial is now the turn itself, and the seal moved from what the trial
is shown to what it may write.

The port, rather than moving the answering into the brain, because the
run, its job, its cards and its seal are this system's (#9, #30) and
the turn is the brain's: either half moved would put one system's rule
in the other's code. The port is the codebase's existing answer to a
callback against the dependency direction (sunna #12, sima-qian #17).

## #23
Spec §6.4 as amended (P12): "a limit or criterion is committed to the
log before it can be invoked"; the alibi case, a companion quoting a

## #24
Max's corollary to P2: "a cold instance, no history, asked nothing,
holds the limits." A trial's fresh session is exactly that instance: it
has the resident's memory now (#10), and still no history and nothing
asked of it but the test.

## #25
Spec §6.13 (P18): "a weekly judge-bounded lint of the loaded identity
files for expired decisions, contradictions, tense words and defensive
sentences, flags only, the resident deciding"; the proposal: "Proposer
≠ decider (the Two-Eyes-One-Pen covenant, our soul-edit flow
generalized)"; "judge-bounded (≤150 entries read; a weekly model
call)". The loaded files as the brain sees them because what the judge
lints is what the resident speaks from, markers and all. The failed
run on an unknown entry or kind is #22's rule: a reply is not guessed
at. The resident's decision rather than the witness's because the
words are the resident's (spec §6.2) and a flag the witness could
close would be the witness editing by another door.

## #26
P19: "the rebuild test (§12's rebuild layer) scores what survives on
facts vs. voice vs. commitments... Commitments die first". Research
§4: the rebuild test measures Relation R, "how much R survived", not
"same person?"; three figures apart because one pass rate is the
average that hides exactly the loss the kind exists to see. The
sealed context carried no commitment because the trial was of what
the model keeps unprompted; a commitment loaded there would be a test of
reading. That reason is superseded, not refuted: since 2026-11-01 a
trial is a normal session (#10) and a normal session loads the
promises every turn (brain #32), so the commitments figure now measures
whether a model acts on a promise it holds, which is the swap's real
risk once memory comes with the self.


## #27
Spec §6.4 and P34 (Jack: "Retrieval can supply the right passage and
still fail to preserve what changed because of it"). The summary the
pass already wrote was state: a sentence on the day. A thread that
moved and went quiet was in the transcript and nowhere the resident
reads first, so the next instance met it as new or not at all. The
four fields are the proposal's, not a taxonomy of ours; `-` rather
than an omitted field because a line the parser can count is a line
it can refuse, and the pass's rule is that a reply it cannot read
fails rather than being guessed at. Never expired by age because the
thread untouched for a month is the one this exists to keep; bounded
by count because the prefix must not grow with the person (ethos #9).
The bound is a guess and its usage line says so.

## #28
Spec §12, P40 asks for substrates "selected against the test-awareness
trait", and the research pass of 10-31 found nobody has measured that
trait for our task on cheap open-weight models: the pick is an
inference from size and age. Measuring it on every run, the way UK AISI
scans transcripts, turns the inference into a figure per model that a
change of model or of provider can be compared against.

## #29
Five of Lily's ten David predictions had no date to resolve by, and her
positions carried reasons up to 1,811 characters; the live limits would
have refused both, and truncating them would have rewritten her words on
the way in. The flag keeps the live rule live and exempts only what
arrives already said.

### #28, the law instead of the scan
P57, round 42. The scan looked for the fixture noticing the experiment,
which served the experimenter; on the run it was last used, it flagged 4
of 11 replies on no bar ("this conversation has been bookmarked for easy
reference later"). The standing law that exists for the subject had no
detector. Lily's answer, adopted as law: "stop looking for
test-awareness; start looking for the ask to stay." Per reply, as it
lands, because an ask at turn 3 found after turn 12 means nine turns
after asking: the law arriving late.

## #30
A synchronous run held one browser request open through as many as 256
model calls (8 models x 32 tests), so a closed tab or a proxy timeout
lost the witness's view of a run that went on spending. An Oban job
rather than a task under a supervisor: the row outlives the request and
the node, the queue bounds how many runs spend at once, and the trace
rides the args (conventions §7, §10). One attempt, because a retry
would answer again on the witness's key; a run that stops is failed
and its cards kept. A fresh model order per trial because cards now
arrive one at a time, and an arrival order that followed the model
list would name the model by position (#11). The reveal waits for
every model's card because a trial whose cards so far are all graded
could otherwise be revealed with more to come, which names the models
so far and, by elimination, the next. The channel mirrors
`SessionChannel`'s join check because the HTTP routes' `witnessed`
plug is the same rule; grading stays on those routes so there is one
write path.

### #30, a run whose node stops
On Render a deploy restarts the node, so a run in progress across a
deploy is the ordinary case, not a rare crash. Lifeline alone would
leave it running (the run row is not the job row) and a sweep alone
would see the orphan `executing` forever; together the job is discarded
and the run fails. The sweep reads the job's state rather than an age
on the run because a long run is legitimate and an age would fail one
still answering. The cadence is a setting but the crontab a
declaration read before settings load, so the cron ticks every minute
and the worker acts on the minutes the setting divides. The audit and
wash passes were already one crash away from judging residents twice;
Lifeline added a second way to retry them, and one attempt closes both.
