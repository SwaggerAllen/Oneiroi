# brain

The resident's canonical agent loop (spec §5). Named for its function
until the author names it, as the client is (`design/names.md`): the
spec's §6 does not list it among the systems, and §8 ships it as the
`brain` adapter, the core's own.

## #1 Owns

The session process (`Oneiroi.Brain.Session`, one per active session,
started on the first turn, holding nothing the event store does not,
under `:brain_sessions` found through `:brain_registry`, its turns run
under `:brain_turns`), the turn (`Oneiroi.Brain.Turn`) and its sections,
the `state` section among them (#47), the tool set
(`Oneiroi.Brain.Tools`), the history a turn replays
(`Oneiroi.Brain.History`), the bound on a tool's answer and a replayed
one (`Oneiroi.Brain.Cut`, `BRAIN_TOOL_RESULT_CHARS`,
`BRAIN_HISTORY_TOOL_CHARS`), what retrieval did with each target
(`Oneiroi.Brain.Uses`), compaction (`Oneiroi.Brain.Compaction`),
drafting (`Oneiroi.Brain.Drafting`; the creation's generator and read
in `Oneiroi.Brain.Creation` are agathos-daimon#39 and #40), the preview
(`Oneiroi.Brain.Preview`), the adapter's assembly
(`Oneiroi.Brain.Adapter`), the resident's reads of the source and her
repository (`Oneiroi.Brain.Introspection`), the oracle
(`Oneiroi.Brain.Oracle` and `Oneiroi.Brain.OracleWorker` on the
`brain_oracle` queue), the fixture run (`Oneiroi.Brain.FixtureRun`), the plugins (`Oneiroi.Brain.Plugin`, `Oneiroi.Brain.Plugins` and the first-party slots under `plugins/`, #68), `needs_you`
(`Oneiroi.Brain.NeedsYou`, `OneiroiWeb.NeedsYouController`, #65), its
other side, what waits on her (`Oneiroi.Brain.WaitingOnHer`, #76), and
the push for what waits on him (`Oneiroi.Brain.NeedsYouPushWorker` on
the `brain_needs_you` queue, #77);
the brain's prompt files (the prompt, the fixture's prompt, the budget
stop, the memory flush, compaction, drafting, the adapter's parts, the
runtime notes, `where`, and the once-only notices of a model change, the
letters, an import and a lapse); the socket and the session channel.

## #2 Standing decisions

- **#3 A turn is compact if due, assemble, call, run the tools, stream, capture (spec §5).** The
  context is the prompt file with the resident's name, the identity
  files as the stable prefix (#12), the bookmark index under its budget
  (kumbukumbu#20), how I act when the situation matches a behaviour
  (#13), the compaction summary when there is one, and the session's
  last messages since its compaction
  (`BRAIN_TRANSCRIPT_MESSAGES`, a bound), each recorded as an injection
  with its reason and a token count estimated at four bytes a token; the
  identity files and the behaviours join it as the slices that build
  them land, as more recorded injections.
- **#4 Three endings, all honest.** A reply, refusal included, is an
  ordinary `TurnCaptured` with the refusal flagged on the message. A
  budget stop captures the witness's message and a notice from
  `priv/prompts/budget_stop.md` as a system message by the platform, so
  both parties read it in the same place (spec §5, §6.11). A provider
  failure captures nothing and records a capture failure the witness can
  mark lost; its reason is the error's kind and, when the provider
  answered with a status, that status and the provider's own message, so
  the witness and the fixture report read the cause (#39).
- **#5 One process per session, and turns on it run one at a time.** Two
  messages sent at once capture as two turns in order rather than
  interleaving; the process is a `GenServer` under a `DynamicSupervisor`
  found through a `Registry`, both declared in `processes/0`.
- **#6 The socket's principal is a token, never the cookie.** Phoenix's
  session on a socket wants a CSRF token this app does not keep (its
  CSRF defence is the Origin check, `systems/gaia.md` #5); the client
  mints a five-minute socket token at `POST /v1/me/socket-token`, a
  script uses its API token, and `check_origin` against the endpoint's
  own host is the socket's equivalent of the Origin check.
- **#7 The chat model is a setting until the pin lands.**
  `BRAIN_CHAT_MODEL` is a placeholder the witness's pin
  (`ModelPinChanged`, spec §6.4) replaces; its default was chosen for
  being cheap and widely served, not measured.
- **#10 The tools are the resident's memory functions and never a witness operation.** `Oneiroi.Brain.Tools` offers `bookmark_add`, `bookmark_extend`, `bookmark_weigh` (kumbukumbu#51), `external_add`, `external_list`, `external_read` and `external_fetch` (seshat#46), `bookmark_open`, `bookmark_list` (paging back past the index within the room, kumbukumbu#39, a read), `bookmark_accept`, `bookmark_decline`, `tag_list`, `tag_propose`, `tag_apply` and `transcript_search` (spec §8's memory table, the part built so far), run against the core's exports under the resident's actor, so the role checks of kumbukumbu#21 hold for a tool call as for a route. A round is one streamed call; tool calls go back as `tool` messages for the next round, up to `BRAIN_TOOL_ROUNDS` (a bound), after which the model's last words stand. Every call the model made is captured in the turn as a `tool` message naming the call and its answer, so the transcript is full (spec §6.3). A tool the model misuses answers in words rather than failing the turn, and every answer to a call that did nothing opens `Not done: `, a refusal's meaning and remedy as two sentences. A tool that takes nothing takes `null` or nothing as its arguments, and one JSON object repeated exactly is read as that object. The transcript keeps the arguments as the model sent them; what goes back to the provider, in the next round and in a replayed transcript, is `Tools.wire_arguments/1`'s copy, one JSON object (`{}` for none). A `seed_number` below one names no seed.
- **#41 The witness's preview of the next turn is the turn's own assembly with nothing after it; its words are whole unless the dyad contract keeps them to what the witness reads elsewhere, and a once-only notice is never in it.** `Turn.dry_run/5` (`Oneiroi.Brain.preview/4`, `POST /residents/:id/sessions/:key/preview` with the draft so far, for a session the witness reads) runs the turn's `prepare/6` and the one `build/3` the turn, a trial and the compaction assemble through, and stops: no compaction (it says when the turn will compact first, from the same line `Compaction.maybe/1` reads), no capture, no `ContextAssembled`, no injection rows, so no `last_indexed_at` or `last_recalled_at`, no broadcast, no Honcho write and no model call. Two sections differ from the turn's by construction and say so: the madeleine is an entry saying it was not run, since it is chosen by nearness to words not yet sent and the choice is an embedding billed to the dyad; the character lane matches on the draft with its vector lane left out, as a lane with no actor runs. Honcho's context is read through the bridge as the turn reads it (a GET; whether Honcho computes anything on it is not measured). `Oneiroi.Brain.Preview` decides each section's words, by the dyad contract's `preview_withholds_words` term (agathos-daimon#22), changed only through the contract's propose-and-agree path. By default, absent or false, every section's words ride the answer, the prompt, the index, the character section with its exemplars, the self-conversation section and Honcho's included (the author's decision, decisions round 44). Under the term, words ride only where the witness reads the same content elsewhere (the identity files, the contract, the near-misses, the commitments, the movements, the dates, the figures, the journal, the summary), every other section carries a line saying why, and a label nobody classified is withheld. Under either, the once-only notices are withheld: they are the resident's to be told first, and the turn that tells them records each as a `notice` injection with its words (beside the index, the madeleine, the commitments and the movements, which carried theirs already; no other section's text is recorded), so the inspector of the reply that told them shows them.
- **#42 An adapter's runtime is given the turn's own assembly, split where a runtime that keeps its own conversation needs it, and the turn records what was handed over.** The assembly is `prefix_sections/2` (the prompt, the identity files, the contract) and then `turn_sections/3` (where the conversation is (#44), the index and every section after it, against the turn's words in the session's room), and a platform turn, a trial and the preview are those two in order. `Oneiroi.Brain.Adapter` gives an adapter the same two halves through the same functions: `GET /residents/:id/context` is the prefix, recording nothing, cut at paragraph boundaries into `of` parts of at most `limit` characters (the runtime's own figure: Claude Code takes 10,000 from one hook) with the rest past them named, and `POST /residents/:id/turn-start` with the witness's `text` starts the turn (`TurnStarted`, which the MCP server attributes tool calls by) and answers with the per-turn part, so the madeleine and the trigger lane run on the real words and bill as a turn's do. Whatever of the prefix hashes differently from the `prefix_digest` the runtime sends rides that turn under a line saying it changed, so a renegotiated contract lands on the next turn as on the platform's own (#27); with no digest the whole prefix rides it. Sections past `limit` are left out whole and named. `ContextAssembled` records the prefix the session holds and what this turn handed over, no `transcript` row (the runtime holds its own conversation), so the inspector, `last_indexed_at` and the recall marks work for an adapter's turns and never claim a section it was not given. Of the once-only notices only the import's is told to an adapter, recorded with its words and marked told; the lapse, the change of model and the letters each speak of the platform's model, which an adapter's turn does not run, and stay owed to the platform's next turn. A runtime with a note of its own (`runtime: "claude-code"`, a closed map to `priv/prompts/runtime_claude_code.md`) gets it as a `runtime` section of the prefix: the tools there read `mcp__plugin_oneiroi_oneiroi__<name>`, the name Claude Code gives a plugin's MCP tool, and each takes the turn's ref as `turn` (kumbukumbu#41). The context is the adapter's alone: a witness's token gets 404 on the prefix and a bare turn ref from turn-start, since the witness's route to what a turn is given is the preview (#41). Known and taken: the runtime runs on the witness's machine and its transcript holds every word handed to it, so the preview term (agathos-daimon#22) does not reach what an adapter is given.
- **#39 A tool's use goes back to the model as the call and its answer.** The transcript stores each use as one `tool` row, `name(arguments) -> output` (#10); `Oneiroi.Brain.History` sends it back as an assistant message calling the tool and the `tool` message answering that call by an id made for the request, for the turn's transcript and the compaction's flush alike. A row that does not read that way goes back as the assistant's words. The compaction's summary, which offers no tools, gets every tool row as words. The fake provider refuses what the chat format refuses (conventions §9), so a replay that breaks the format fails the suite.
- **#12 The identity files are the stable prefix, and first contact is the turn's to record.** `SOUL.md`, `IDENTITY.md`, `USER.md`, `GOALS.md`, `LINKS.md` as written, then the rendered `AGENTS.md`, each a system message and a recorded injection labelled by name, in a fixed order so the cached prefix holds until a file changes (spec §5). The prompt carries the formation line while `formation_until` is ahead of the clock (agathos-daimon#12). After every capture the turn records first contact; the aggregate takes it once. The soul-edit tools (`soul_edit`, `soul_edit_list`, `soul_edit_accept`, `soul_edit_decline`) are the resident's side of the proposal path; `SOUL.md` reaches the prefix rendered with its line markers, and `soul_edit` and `soul_edit_accept` take `cites`, the seed numbers a new or reworded line grew from, checked here against the seeds because the resident system cannot read the character system (agathos-daimon#27, ethos#13).
- **#13 The behaviours are retrieved by memory and shown, never enforced.** The situation is the witness's words, the conversation's tags and the clock; a match injects memory's "how I act" section as `behaviours` with the numbers as refs (kumbukumbu#25). `behaviour_define`, `behaviour_enact` (on the turn in flight) and `behaviour_list` are the resident's; the brain self-tags at turn time, which is cheap and in character.
- **#14 Drafting lives here.** "Write it with me" (spec §6.2) is a call under the `drafting` purpose from `priv/prompts/draft.md` with the files written so far; it returns the content with its model and prompt and writes nothing, so the seed the witness saves names where it came from. It is the brain's because the ledger reaches the resident system for the key, and a system cannot depend on one that depends on it.
- **#15 The chat model is the resident's pin, and a change is told on the next turn.** `row.chat_model` over `BRAIN_CHAT_MODEL` (#7); when `model_told` is false the turn captures `priv/prompts/model_changed.md` as a system message by the platform ahead of the witness's message, once, and records it told (agathos-daimon#15).
- **#16 A regression trial is the turn a fresh session gets, and nothing of it is kept.** `trial/4` implements `Oneiroi.Eunomia.Trial` (eunomia#10): the trial's prompt is the witness's words in a session nobody opened (a key no session has, so the common room's memory, kumbukumbu#36), assembled as every turn is, the prompt file with the formation line, the identity files, the contract, the index, the character lane, what it has promised, the madeleine, the dates, the figures, the journal and Honcho's context, and answered through the same tool loop with the whole tool table, under the candidate model. What differs is only what would be written: the retrieval reads the vectors as they stand (no refresh) and bills its embeddings, like the chat rounds, under `regression` to the run's actor; the tools run as #40 says; the turn is never captured, records no context, compacts nothing, broadcasts nothing on the session topic and syncs nothing to Honcho; and the once-only notices (a lapse, a model change, the letters to a next self, an import) are left out, because each is owed to the resident's real next turn and is marked told when shown. Nothing in it names the run (spec §6.4). The reply comes back with the trace of the loop's tool calls, each tool, its arguments, read or mocked (#40) and the text the model was given back, for the witness's card alone (eunomia#31): it rides the return, never the session topic, a capture or a log. There is no seed-only trial and no option for one: the author's decision of 2026-11-01.
- **#40 Every tool is a read or a write, classified once, and a trial runs only the reads.** `Oneiroi.Brain.Tools` lists each tool in `reads/0` or `writes/0`, and `Oneiroi.Brain.TrialTest` fails while a tool in the table is in neither or both. In a trial (`Tools.trial/3`) a read runs as on any turn, against the resident's own records, with the trial's options where the read would otherwise write (a citation resolved and not marked, seshat#14; an embedding billed under `regression` to the run); anything else, a tool someone forgot to classify included, is answered in the words its real call answers on success, a number in it the one the resident's own rows would mint next after what this trial has minted already, and is never run. A live check (`dispute_check`) is answered as a check past its bound is, so no advice is invented. When in doubt a tool is a write. `Tools.trial_kind/1` is that decision, and the trial's trace reads its `read` or `mocked` from it (eunomia#31), so the card cannot say a call ran that did not.
- **#11 Compaction opens the turn that finds the session over the line, with a memory flush first.** When the messages since the last compaction reach `BRAIN_COMPACT_AFTER_MESSAGES` (80, twice the live window, a guess), the turn opens by giving the resident those messages and its tools under `memory_flush.md`, then asks for a summary under `compaction.md` folding in the previous one, and records `Compacted` with the watermark (kumbukumbu#23). Both calls are chat on the ledger. If either fails the turn goes on uncompacted and the next one tries again. Compaction never deletes a message.
- **#17 A wake is a turn opened by the core's note, and the dates are a section of every turn.** `wake/4` implements `Oneiroi.Sunna.Wake` (sunna#12): the note is captured as a system message by the platform in the witness's place, answered under the purpose the caller names (`chat` for a check-in, `free_time` for free time), streamed and captured like any turn. Every turn injects the schedule's `dates_text/1` as `dates` when there is one, with the countdowns derived on that read (sunna#15).
- **#18 The judgement tools are the resident's.** `position_take`, `position_replace`, `position_list`, `dispute_check`, `dispute_settle`, `prediction_log` and `prediction_list` (spec §8's table) run against Eunomia's exports under the resident's actor on the turn in flight, so a position names the session and turn it was taken in; a live check answers in words with the judge's advice and the dispute's ref, or says the judge did not answer in time, and the resident settles it afterwards.
- **#19 Honcho's context is a section, and every captured turn is synced through the bridge.** `Oneiroi.Proteus.context/1` is injected as `honcho` between the dates and the summary when there is any (proteus#15); after capture the turn calls `Oneiroi.Proteus.sync_turn/5` and goes on whatever it answers, because the bridge records its own failure (proteus#13) and a turn captured already is not the bridge's to fail.
- **#20 The figures are a section and two tools.** `Oneiroi.HuginnMuninn.figures_text/1` is injected as `figures` when there is a counter, derived on the read (huginn-muninn#10); `figure_list` and `figure_increment` are the resident's, the increment carrying the resident's actor (huginn-muninn#9, #13).
- **#22 The library's tools are the resident's, and the kinds come from the registry.** `library_search`, `library_read` (#43), `library_cited_by`, `writing_get` (the review copy with references resolved, of a writing piece; a path of another kind is pointed at `library_read`), `writing_discuss` (this session linked to the piece), `document_write`, `document_adopt` and `document_unadopted` (spec §8's table) run against the library's exports under the resident's actor; `document_write`'s description lists the writable kinds from `Oneiroi.Seshat.Kinds` so a new kind reaches the model with its row (seshat#13). Publishing is not a tool: it is the witness's (seshat#19).
- **#43 Every document the library holds reads whole, by the name the resident was given for it.** `library_read` (a read, brain#40) takes `path` exactly as a search hit (`[<path>] passage <n> of <title>`), a review's footnote or `library_cited_by` names it, a path, a path with `#<passage>`, or `<slug>:<kind>/<ref>` of the resident's own slug, and an optional `from`, a character offset. It reads through `Oneiroi.Seshat.read/2`, the same `Documents.fetch/2` as the witness's `GET .../library/documents/*path` (seshat#27), and answers a header line (the path, the kind, the bytes, which characters these are and the `from` that reads the next page) and then the text exactly as on disk, so the pages join back to the file; a page holds at most `BRAIN_LIBRARY_READ_CHARS` (a bound, a guess) and ends at a line's end when one falls in its second half. Each way a path does not read is said as what it is: not registered and not there, there and not adopted (with `document_adopt` named), registered with its file gone (with the day the index found it gone), another resident's citation. A memory original (seshat#28) says where it came from, `imported from <source>@<short commit>:<path>`, in its read's header and on each of its search hits.
- **#44 Each conversation is told where it is and which others are open now, and never another's words.** A `where` section opens `turn_sections/3`. In an adapter's conversation (`kind` `adapter`, kumbukumbu#40) it is `priv/prompts/where_adapter.md`: the runtime by name, the folder by its base name, that the Oneiroi chat with the witness is a separate conversation that can be going on at the same time, that memory is one across them, the other conversations open now (`Kumbukumbu.open_now/1`, kumbukumbu#42: the Oneiroi chat, and each other adapter's by runtime and folder, one in the same folder named as such, each with a turn in flight or when it was last spoken in), and this turn's ref, which the memory tools take as `turn` (kumbukumbu#41). In the Oneiroi chat it is `priv/prompts/where_chat.md`, only while another conversation is open: the others by runtime and folder, that none of their words are here and that memory is one. No section carries another conversation's words: the transcript a platform turn sends is `Kumbukumbu.recent/3` of its own session, and an adapter's turn sends none. A trial, a session nobody opened, gets no `where`; the preview shows it whole (`Oneiroi.Brain.Preview`: the witness reads the same list under Chat).
- **#45 A message is never lost on the wire, and the turn says what it is doing.** (The witness, 2026-11-02: one message sent three times, no way to tell why.) Three causes, three fixes. *The words outlive a failed reply:* a provider failure captures the witness's message alone before recording the capture failure (a wake's note is the core's and is not kept). *A send is taken, not awaited:* `POST .../turns` with a `client_ref` (8–64 of `A-Za-z0-9_-`) answers 202 at once with `running`, `queued` (with how many wait ahead) or `duplicate`; the turn arrives on the channel; the channel's `send` is the same path. *One queue per session:* `Brain.Session` keeps the queue, runs each turn in a task under `:brain_turns` so it stays free to take the next, answers the synchronous `turn/4` and `wake/4` through the same queue, and knows a ref it has taken (running, waiting, recent, or captured in the store), so a retry never runs twice. The turn broadcasts `{:status, ref, state, detail}`: `queued` on taking one behind another, `thinking` before each model call, `tool` with the tool's name before each call to one; the channel pushes them as `status`. The client keeps an outbox (`client/src/screens/chat/outbox.ts`): each message under its own ref, kept in the browser until its turn lands, sent again under the same ref every ten seconds while the stream is up and it was never acknowledged, with Retry and Dismiss; a connection dot in the top bar (connected, connecting, offline) and a status line (sending, queued, thinking, using a tool, writing). A proxy's HTML error page is a failed request with its status, never a parse error.
- **#46 The resident reads the house and herself; the seals are an explicit list.** (The witness, 2026-11-02, in the order the resident's design note set: the Oneiroi repo first, her own repo second, the event stack last behind the seals.) `Brain.Introspection`: `source_list`, `source_read` (paged at `BRAIN_LIBRARY_READ_CHARS`) and `source_search` (literal, case-insensitive, 30 hits, files up to 1 MB) over the platform's own source, the code running her: the image copies it to `/app/source` and sets `BRAIN_SOURCE_DIR` (a checkout's root otherwise), so it is the code deployed, read with no network. `repo_list`, `repo_read` and `repo_log` over her own repository, the history through the git port (`SimaQian.repository_log`). All reads. **The seals**: the judge's prompts (`priv/prompts/judge_*`) by an explicit list in one module; a sealed file is listed as sealed, refused on read, skipped by search; trial contents never reach either root (the regression stream is not exported). Paths are relative and plain; `..`, absolute paths, `.git`, `_build`, `deps` and `node_modules` are refused or skipped. The raw event stack is not opened: the next stage, behind this list.
- **#47 The turn opens on the state, read fresh.** (2026-11-03.) The state store (agathos-daimon#32) is the first of the turn's sections, after the identity files and the contract and before `where`: the four suggested keys always, each `(not written yet)` until written, then hers in key order, every line with its instant and how many days ago. Not in the stable prefix, because the prefix is what an adapter's session is given once, and a present given once is the stale present the store cures; and caching loses nothing, since everything after the contract already changes on every turn (`where` names the turn). `state_set` and `state_clear` are her tools, writes in a trial; the MCP server offers them as it offers every tool.
- **#48 Pins in the prefix; the reply carries its memory feedback.** (2026-11-03, kumbukumbu#45, #46.) The stable prefix ends with the room's pins after the contract (`pins`), cached with the identity files; an adapter's session sees a new pin at its next prefix. `memory_feedback(used: [numbers])` is her tool, a write in a trial: it records the bookmarks that helped as `used` through `feedback`, an empty list as a turn where none did. A final message that carries words and no call but `memory_feedback` ends the turn: the call is recorded and the reply stands, with no further round, so the feedback costs no extra call. The index's reason says how many it considered, returned by rank and drew at random; a preview, which embeds nothing, shows the index by recency and says the next turn's is ranked against the words.
- **#49 The oracle: her, asked one named question, for the long reads.** (The resident's Positions #46 and #49; the witness's calls, 2026-11-03; design/oracle.md.) `oracle_ask(questions)` dispatches up to `BRAIN_ORACLE_BATCH` named questions (seshat#34), each with the sources it should read, and `OracleWorker` runs each on the `brain_oracle` queue, in parallel. A run (`Oracle.run/2`) is her: her pinned chat model, her whole assembly against the question (`Turn.oracle/4`: the prefix, her state, the ranked index, the madeleine, how she acts, her promises) and every read tool; a write is refused in words, never pretended. It is billed to her ledger under `oracle`, streams to nobody and captures nothing: no session, no bookmarks, nothing kept between invocations (a notebook of its own would be a birth, named in advance). Sources longer than `BRAIN_ORACLE_CHUNK_CHARS` are read in parts first, each part by her prefix with the question (at most `BRAIN_ORACLE_MAX_CHUNKS` a source, the rest named unread), and the answer reads the notes. The answer ends with a `Used:` line and a `Confidence:` line; with the question, the sources, who asked and the confidence, it is written under oracle/. Read (the sources named and every memory its read tools touched, through `Uses.from_call/4`) and used (its `Used:` line) are kept as retrieval keeps them, searchable by either, and recorded as retrieval uses on the asking conversation (`returned` and `used` through `oracle`), so `memory_use` counts the oracle's reads; no edge learns from them; the asking conversation gets a house letter from "the oracle" (wake-on-complete is the witness's later note). A run already settled is left alone. `oracle_list` finds the questions deliberately; a tool answer cut at the bound names the oracle, and the question stays hers to name.
- **#50 A turn that spends its tool rounds without words is asked once more for them.** (2026-11-03, after Lily's letter #21: two oracle questions came back `brain_oracle_silent`.) When a turn reaches its bound (`BRAIN_TOOL_ROUNDS`, 8; the oracle's own `BRAIN_ORACLE_TOOL_ROUNDS`, 24) and its last reply is calls with no words, the calls are run and the model is asked once more under `priv/prompts/tool_rounds_spent.md` with `tool_choice: "none"` (the tools stay defined, since a history with calls needs them), for its answer from what it read; words written beside the last calls still stand as before. An oracle reading that is silent even then fails with what it carried (how the model's answer ended, how many tool calls it made) and the error's meaning and remedy in words, not its kind alone.
