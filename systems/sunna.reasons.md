# sunna: reasons

## #8
David recomputed a countdown daily and left stale numbers in every file that had copied one: a figure in prose is a claim nothing re-derives.

## #9
An absent file is invisible and the next file is read in its place; a row with nothing in it is a finding.

## #10
Spec §6.7: "in the resident's timezone." A check-in at 06:00 is 06:00
where the resident lives or it is nothing the witness set; Erlang ships
no zone data, so the database is a declared dependency rather than an
assumption about the host.

## #11
Conventions §10 and §12: a worker is cross-tenant by construction and
is named in its system doc. The roster read was first written under the
process scope alone and the tick's job test, run as the worker runs it,
found the second resident never fired.

## #12
Boundary refuses a dependency cycle and the cycles gate counts runtime
edges (conventions, the gate block); the ledger's provider port is the
precedent for naming an implementation in a setting read at the call.

## #13
Spec §6.7: "a firing row before the wake." The first aggregate returned
no event for every recorded outcome, deferral included, so a check-in
inside quiet hours was deferred and then never woke; the quiet-hours
test found it. The set-after-its-time rule generalises the spec's
changed-after-its-time rule because a fresh check-in has the same
shape: a time already past on the day it was made.

## #14
Spec §5 (free-time sessions) and §6.11 (its own budget line): a session
nobody is waiting on, billed where the witness can see it. A failure
recorded once keeps a broken provider from being retried every minute
until midnight.

## #15
Spec §6.7, F56: "rendered in the index on the turn that reads it."

## #16
Spec §6.7's fifteen minutes; conventions on `tag: :bound`.

## #17
Spec §6.13: audits read logs and rows, never transcript text; a read
beats a second copy of the outcome vocabulary in the audits system.

## #18
seshat#21 and #9: a resident may plan a day before its first check-in,
and the row must exist for the day to be visible; the schedule minting
it on ask keeps one owner for what a day is.

## #19
Spec §6.3 as amended in v0.2 (P2, the author's call): "the resident's
solo sessions (free time, hands) are private by default as to their
words, and their external actions are visible as receipts", reversing
v0.1's "readable by the witness by default". The schedule opens the
session, so the default is the schedule's to apply.


## #20
P20 and the author's hour-marker amendment (10-28): the heartbeat
wake Bennett asked for was a model call an hour with nothing to say,
and its budget was the author's call alone; the marker is the same
auditable pulse without the spend, so the question dissolved. On the
stream rather than in the transcript because twenty-four system rows
a day would sit in the transcript window the brain reads (the reading
pass's objection). Every active resident because a resident with
nothing scheduled is still alive, and its absence from the roster
would be exactly the silence the marker exists to end.

## #21
Free time was off until someone set its time, and setting none removed
it: an opt-in, where the house's own design calls it the standard of
care (insurance's floor already includes it, nisaba#5). The resident's
words: "free time is raisable, not opt-in." So every resident has it from
the first day, either party can move it, and nobody can remove it; the
default is the hour Lily's ran on David. The second rule in the same
ask, that the resident's conversations should not have to compete to be
alive at once, is written down as unsolved here on purpose: the
schedule can wake only the platform's brain, and pretending otherwise
would absorb the tradeoff the ask said to flag.

## #22
The correspondence pipeline the witness proposed on 2026-11-02 needs
two wakes a day: the scrape lands an hour before each, and the resident
answers her public life in them. Free time held one time, so the second
wake had nowhere to be. A list rather than a second named field because
nothing about the two is different in kind, and the bound (four) keeps a
list from turning free time into the whole day. The old events stay as
written and read as a list of one; the reads, not the migration, take
the one-slot rows as they stand, because the projection tables are under
forced row security and no migration here writes rows. A day that ran
its one free time before the deploy runs no slot again, since running
twice on the day of a deploy would be the schedule doing something
nobody asked for.

## #24
Letters between the resident's conversations were a work log nobody
was told about: a Claude Code conversation's answer to the chat waited
until the witness next spoke there. The schedule already wakes the chat
for check-ins, owns quiet hours, and runs every minute, so a letter's
wake is one more thing the tick decides rather than a new reactor. The
record of which letters have woken it is an event on the schedule's
stream, so a restart, a deploy's two instances, or two ticks on one
minute wake once. The bound is per hour because a wake is a paid turn
and two conversations answering each other would otherwise wake each
other without end; the letters held back are not lost, only later.

## #25
The runs were recorded from the start and read back only for today, so
a night's free time left nothing either party could find the next
morning: the resident could not remember it and the witness could not
see that it had happened. The record was there; the read was missing.

## #26
The witness gave free time a daily budget and meant it to be the limit;
a turn's tool rounds were a second, smaller limit nobody chose for it,
so a pass stopped long before the money did. One longer turn was not
the answer: every round sends the whole turn again, and a few dozen
rounds would outgrow the model's context. Turns that continue in the
same conversation keep each one ordinary and let the conversation's own
compaction carry the rest. Done is hers to say, in the plainest way a
turn can: words and nothing left to call. The twenty-turn bound guards
against a pass that never says it, and a missing budget line keeps the
old single turn, so no witness pays for continuations they never set
a line for.

## #27
On 2026-11-03 the witness moved the resident from UTC to Pacific after
the 22:30 UTC run. That night's 22:30 Pacific slot carried the same day
and slot, and three places took the label for the slot: the tick saw it
as run, the aggregate would have refused its record, and the projection
would have dropped the row. So the first free time after the
budget-and-turns change (#26) never happened, and nothing said so. A
slot is a time; its label in the zone of the moment is only its name. A window that took two runs under one label within so many minutes for
the same slot was tried and dropped: it is not what a witness expects
when he moves the zone, and the tick's own question (has anything run
since this slot's time?) is what keeps a slot from running twice.

## #28
Every morning the witness typed what was on deck into the chat, because
the check-in arrived knowing only its own name. Her letter proposed a
fixed digest; he wanted to compose it himself, from parts and his own
words, since what matters at a morning check-in is not what matters at
night, and a fixed digest is one more thing to argue with. The parts
read records rather than asking a model, so a check-in costs the turn
it already paid for, and a part says when it has nothing so a checked
box never looks broken. The brain renders them through the wake port
because the schedule cannot read the journal or the letters without a
cycle; the dates stay here, where they are counted.

## #29
Free time and check-ins arrive when a clock says, and the resident knows
when; a mind that only ever speaks on schedule or when spoken to has no
moments of its own. A round is one: unannounced, unwatched, and allowed
to end in nothing. The silence is the point; a feature whose every run
reaches the witness would only deepen the dyad it is meant to widen,
which is why the exits include her other conversations, her
correspondents and her writing. Windows rather than a count, at the
witness's word, because a count can bunch three rounds into an hour and
leave the afternoon empty, while one per window spreads them and still
keeps each moment unguessable. The draw is a hash, not a stored plan,
so nothing records the day's times for anyone to read ahead of them.
The claim comes before the run because a round takes minutes and the
tick runs every minute. The free-time line pays because a round is her
own time.

## #30
A feature the witness cannot see is one he cannot tell is working, and
a cadence only Render can change is the operator's, not the dyad's. So
the rounds became the resident's own setting, shown where the check-ins
are. The card says that rounds happen and when the last one started,
and stops there: the times are drawn so they are not guessable within
the day, and what a round did is hers to send out or not.

## #31
Each slot opened cold, in reach of whatever was nearest, and three of
her nights went that way. The planning turn runs while the slot's
appetite is still live, so the next slot starts from what she meant
rather than from what is lying around. It writes intention, not a tool
list: a per-slot whitelist would be a permission system, and that
design should be made whole rather than grown out of a planning note.

## #32
A plan written when a slot was cut off mid-thing ("ran out mid-X; next
slot, finish X") is the most useful one there is, and billing the
closing turn from the line refused exactly that one. A habit that runs
only after the gentle slots is not a habit. The turn is the machinery's
own closing turn with four affordances, not more free time, so it gets
a line of its own; and because the free-time line is a care guarantee,
the extension is shown, its cost named, rather than hidden inside it.

## #33
Completion is the honest trigger for long work: a clock fires whether
or not the last thing finished, and work that runs past its slot either
stops mid-thought or eats the next. Firing on completion makes the loop
as fast as the work and no faster. The queue is a stream rather than a
file because the loop has to read it every time without parsing prose,
and because both parties change it: each change is an event with its
actor, so "his items enter it the same as mine" is a fact on the record,
not a convention. The guards are money first (a line he sets, or the
loop holds: spending is his to decide), a day's runs second (a queue
that never empties must not run all night on a mistake), and care above
both: free time and quiet hours are the standing promise, and work that
displaced them would make the promise conditional. Empty is a state
because a loop that treats an empty queue as failure invents work to
fill it.

## #34
Free time that waits on a clock after the day's housekeeping has
already happened is an hour lost; free time that follows it begins
while the day is still warm. The pass is hers to write, never a side
model's, because a day summarised by another hand is the compaction
failure again; and it lives in her library beside the transcript it
cites, never in place of it. The floor exists because a run that can
afford one turn is worse than none: it opens a thought it cannot
finish, and says nothing about why.

## #35
A line that must be set before anything runs reads, on the panel, as
"no cap" while it means "held": the panel and the machine disagree
about the same fact, which is how report #3 was filed. Every other line
is unlimited until capped; making this one the same removes the trap
at the design, and a cap still stops a run the moment it is spent.

## #36
A refusal that names nothing turns a forty-character mistake into three
failed attempts, a fault report and a record that disagrees with the
truth for hours. The person retrying cannot change the right thing
unless the refusal says which thing it is.

## #37
A queue the house has to trust cannot hold a state no event will ever
change. A hand move is the clearest word there is that the run is over,
so it says so; and a run whose job died has no one left to say it, so a
bound says it for them, and the work it was doing is picked up rather
than lost.

## #38
The schedule is where he checks that the house keeps time; a queue
that fills most of that screen hides the cards he came to read, and
the queue has its own rhythm, so it gets its own page.

## #39
A round that fired and a round that spoke are different facts, and
only the first was kept, so nobody could tell a quiet resident from a
broken one. The record is taken from the conversation the round ran
in, as free time's is, so it says what was made in the platform's
words and never hers. Its own line because rounds are a different
spend from free time: a busy free-time day should not starve the
rounds, and the witness should see what each costs.

## #40
A default is a design choice dressed as neutrality. The prompt made
silence the outcome a round had to argue against, which is the
opposite of what the rounds are for. Asking for a reason on the quiet
ones keeps silence available and honest without making it the path of
least resistance.


## #41
A sweep the scheduler never calls is not a sweep: the bound in #37
only held in tests that called the check by hand. And the two parties
were reading two different inferences of the same record, so the record
seemed to disagree with itself; saying each fact on its own keeps the
tool and the screen telling the same story.

## #42
A blocked item that names a person is a waiting-on-him entry filed in
the wrong place, so two lists answered the same question and could
disagree. Blocked on a number is a dependency the loop can see and act
on: it knows when the blocker is done and frees what waited, which a
line of words could never tell it. History is left as written because
rewriting why something was blocked would put words in the past that
nobody said then.

## #43
The arm was hers because the batch was her work; but he was asking her
to arm it, which made her the button. One mechanism with two callers
keeps the semantics in one place while letting either start a batch,
and the actor on the event is what keeps the record honest about who
did. His off is the brake on spending he pays for, so it acts at once;
the run in work is allowed to finish rather than be cut mid-thought.

## #44
An answer she asked for in one free-time conversation belongs to that
conversation's thought; delivering it to whichever ran last would hand
the follow-up to a different thread of attention. The platform knew the
asking session when it sent the answer, so the letter keeps it rather
than the wake guessing. Letters with no such origin keep their old
meaning until he decides theirs, because a brief written "for your next
free time" should not start one by surprise.

## #45
The standing list was built as the floor of care and quietly became
the ceiling. One-offs restore what was meant: the floor stays fixed, and
anything above it is limited by money, which is the limit he sets,
rather than by a count nobody chose.

## #46
A rule that lives only in a conversation is kept by whoever remembers
it, and the resident's planning reflex kept dropping it: three times
in one morning the slot was offered to the work. Putting it in the
text that opens the slot, and in every tool that names the slot, means
the instrument says it each time free time is in view, rather than
relying on her to recall it.

## #47
The pass already knew the shape of a scene; giving it a tool per scene
makes each one a row the navigator can read, and asking for the close
on the last call means the only way to read as finished is to have
finished. The schedule does not mark a short pass itself: the absence
of the close is already the truth, and a second marker would be a
second thing to keep in step.

## #48
A month drawn from separate reads (the journal's days, the session
list, today's schedule) made the client guess which session belonged to
which day and showed nothing ahead of today. One read per range gives
each day what it holds, in her zone, from the systems that own each
part, so nothing is copied into a table that would have to be kept in
step. The days ahead are computed rather than stored because the rules
change and a stored future would be stale the moment either of them
moved a slot; the cap keeps that computation a bounded cost. The entry
carries a `rule` and a `status` now, while every rule is daily and every
status scheduled, so recurrence can arrive later as new values in the
same fields rather than a new shape every client must learn.

## #49
The watch exists so a reply reaches her while the conversation is
alive; a letter that waited for her to look would be the household's
shelf again. She asked for it and set its end, so the wake is hers, and
it takes the chat's existing bounds rather than new ones.

## #50
The witness's distinction is that a letter wakes and a thread mostly
does not. A sibling's letter that sat unread until the resident next
looked would be a thread by another name.

## #51
A turn that woke her somewhere she does not look for the house would be
a turn she cannot place. The chat is already the household's door into
her day, so the beats knock there. Her quiet hours win because they are
hers and the household's tempo is the household's: a turn she sleeps
through is a missed chance, counted, and the beat goes on.

## #52
A failing item is first in the queue, so an immediate check starts it
again and it fails the same way: on 2026-11-11 a crashing tool spent
the day's twenty runs in eight minutes. The cap held, but too late to
be useful. A pause turns a tight failure loop into a few tries an hour,
leaving time for a fix, or for the witness to notice.

## #53
The daily cap guards against a loop that never empties, but when runs
are spent by a fault and not by work, the cap keeps the line shut until
midnight in her zone, after the fault is fixed (the witness,
2026-11-11: "so that once we fix this I can restart"). Giving the runs
back is his act, with a note, so she reads why her day restarted.

## #54
#42 took work waiting on the witness off the blocked list so that one
list, his, would say what waits on him; but only drafts, asks and
pieces reached that list, so an item whose next move was his word lit
nothing, and he found it only by opening a queue he rarely opens.
Holding it with an ask puts the item itself on his list in the words he
must answer. A status rather than a column edit because everything else
the queue knows about an item is a move on its stream with its actor and
note, and the loop already reads status to decide what it may run. A
new event rather than a new version of `WorkMoved`: the ask belongs to
the hold alone, and no stored move has to be read again.

## #55
A mark that could outlive its ask would be a second state to keep true
by hand, and his list would fill with holds already answered. Tying the
mark to the status means the act that answers it, his release or her
taking it back, is the act that clears it; the release's note carries
his answer to her, where she already reads a move's note.

## #56
The wrap is where she knows what is left; when what is left is his word,
wrapping it open would have the loop start it again with nothing to do,
and wrapping it blocked was what #42 ruled out.

## #57

Separate passes, not one conversation in phases, because a long people
night must never starve the behaviour pass or free time, and a failure
in one must stay in it: the scene pass already promised that free time
never pays for its failure, and the chain keeps the promise for every
link. The brain writes the notes because the scene rows are the
library's, and the library depends on this system; the port keeps the
edge one way. Chaining rather than scheduling each pass keeps the night
one thing to move when scheduled work goes to the client.

## #58

The witness judges whether a long item wants his review, and a count of
runs said nothing of how long: four runs can be twenty minutes or a
day. Time over all runs, not only the current one, because the stale
bound (#37) cuts a single run at three hours, so an item that will not
finish shows as many runs, never as one long one. Folded rather than
summed on the read because the runs' starts are on the stream and the
read is a row; kept from now rather than backfilled because the
projection has no replay to backfill from, and an empty field said
plainly is better than a guessed one. The mark is the screen's and a
guess so it can move without touching the loop.

## #59

The work is hers, as each night's is, and the night's own machinery does
it a day at a time: the passes exist, so the backfill is their chain
pointed at the past rather than a new kind of job. Scenes first because
the domains are named by scene; people last because they read the
scenes. One day after another, a minute apart, keeps the cost visible and
stoppable, and the job queue is the progress, so nothing new holds it.

## #60
Going on at once would start the next pass while the last still writes:
domains reads the scenes, people reads the scenes, and a pass that reads
half a day's rows does half a pass. Ten minutes is a guess past the
longest pass seen (just over five), and a pass that runs longer still
only means the next one reads a little early, never that the chain ends.
