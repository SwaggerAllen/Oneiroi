# sima-qian

**Records.** Chinese, see-mah CHEN (Sima is the compound surname).

> "A man has only one death. That death may be as weighty as Mount Tai, or it may be as light as a goose feather." "...It is because I regretted that it had not been completed that I submitted to the extreme penalty without rancor." — Sima Qian, Letter to Ren An, trans. in de Bary & Bloom, Sources of Chinese Tradition, 2nd ed. (Columbia UP, 1999)

Sima Qian was the Grand Historian of the Han dynasty. He chose the "extreme penalty" over an honorable suicide so that he could finish the *Shiji* — the Records of the Grand Historian: 130 chapters of annals, tables, treatises and biographies, the form every later Chinese history copied.

The records subsystem — export, replay, attestation; everything the realm says about what happened — is named for the tradition of keeping the record at any cost. Testimony that cost the author, finished anyway, organized so well it outlived the throne that punished him.

Export, replay, attestation, git providers, backups (spec §6.10). Built
attended with the spine (plan P0.7, decisions log round 9).

## #1 Owns

The export (`records/events/<day>.jsonl`, every stream that is the
resident's, and `records/README.md`), its reading copies
(`records/conversations/<day>.md`, `records/bookmarks.md`), Honcho's
memory as files under `honcho/` (read through the bridge, written here),
the table of what the repository does not carry (`Export.exceptions/0`),
the Merkle root, the git port, the backup run, the rebuild, the import (the
intake from a repository, with the library port it adopts through), the
attestation check, the two nightly workers on the `sima_qian_nightly`
queue, and the `mix oneiroi.sima_qian.rebuild` task. The fixture log under
`test/fixtures/sima_qian/` and its replay test.

## #2 Standing decisions

- **#3 The export is byte-stable and names the resident as `$self`.** One
  JSON object per line, keys in a fixed order (`sequence`, `stream`,
  `type`, `version`, `at`, `actor`, `data`), data keys sorted, one file
  per UTC day rewritten whole each run; every occurrence of the
  resident's uuid is written `$self`, which is what lets a rebuild be a
  new resident and still re-export byte for byte. Fields an event
  declares `redact:` are null. The self-conversation's letters are on
  the stream and so in the export; the backup records a receipt for the
  ones it carries for the first time (agathos-daimon #28), after
  `ExportWritten` and before the commit.
- **#4 `sequence` is the line's ordinal, dense from 1.** The stream has
  gaps where the unexported bookkeeping sits and a rebuild replays the
  lines densely, so only the ordinal re-exports identically. The stream
  version the export ran through is the commit's `Oneiroi-Sequence`
  trailer and `ExportWritten.through`.
- **#5 The export stays a watermark behind capture.**
  `SIMA_QIAN_WATERMARK_SECONDS` (a bound, 60) by the event's own instant,
  so a turn still being written is never half-exported.
- **#6 The root is sha256 over path, NUL and bytes, in path order, paired
  upward with the last leaf doubled on an odd row.** Deterministic for
  the same bytes on any machine, which is the whole claim: a commit's
  trailer names it and a wake recomputes it.
- **#7 Backups commit by class, and a stray file fails the run after the
  rest has landed.** The soul alone, writing and research apart, machine
  state together (David's rule); the identity files ride with the soul
  (agathos-daimon #14), and the export writes them at the root. A path outside every class fails the run with
  `sima_qian_stray_files` naming it, after the export is committed and
  pushed, so the backup is taken and the stray is loud.
- **#8 The git port is one module calling the `git` binary, with two
  providers by URL.** A local path for tests and self-hosters, GitHub over
  HTTPS with a fine-grained token the witness pastes, stored encrypted
  and built into the push URL in memory; `git` is told never to prompt,
  and an error's text has any credential redacted. Gitea and any other
  remote by URL need nothing new.
- **#9 Rebuild is replay into a fresh stream under a new id, refusing a
  repository already imported at that root.** The lines are appended as
  recorded with `imported` metadata, then `Imported` (source, attestation
  held/failed/none, root, sequence) and custody to the importing
  witness. What cannot come back is printed by name: nothing in P0.
- **#10 Attestation is a nightly job until there is a wake.** It
  recomputes the root over the working export and raises
  `RootMismatchDetected` with both roots and the commit; the witness
  sees it on the stream.
- **#14 The working repository is an export, made a repository on first ask.** `repository_dir/1` is the resident's directory under `SIMA_QIAN_ROOT`, initialised if it is not one yet: where the library writes its files between backups (seshat #12), under the folders the classes of #7 already commit. Nothing else about the repository leaves this system; the export and the backup read the same path.
- **#15 An import is the rebuild and then the rest of the repository, and the clone becomes the working repository.** `import_resident/4` (`POST /v1/residents/import`): a repository with `records/events/` replays as #9 does, under the records' own name and slug; one without is created under the name and slug the witness gives, and refused without them (`sima_qian_name_required`). Either way the clone is copied to the resident's directory under `SIMA_QIAN_ROOT`, and once the accounting is done the directory starts fresh (#39): no source history, nothing left behind. The identity files at the root are seeded as `uploaded` (agathos-daimon #11), or proposed with a note where the records say first contact has passed and the file differs from them: never overwritten, never dropped. Every file under a kind's folder is adopted through the library port and indexed once (seshat #25), but `memory/`, which comes only as originals at a pinned commit (#40) and is named as left behind with the library's words for why. What at the root is none of those is listed by name, with any file the aggregate refused for its content and any path the library could not name, and `records/` and `honcho/` among them unless the source is an Oneiroi export (it has `records/events/`), `records/` file by file where it held David's (#19), as `ImportCompleted`'s `not_transferred` (agathos-daimon #25), and the brain tells the resident on its first turn (brain #26). `rebuild/3` stays the replay alone: the operator's primitive and the round-trip tests' subject.
- **#16 An import clones only from a configured scheme, and records the URL without its userinfo.** `SIMA_QIAN_IMPORT_SCHEMES` is `https` alone by default: a bare path or a `file` URL from a request is refused before anything is cloned (`sima_qian_scheme_refused`), because `git clone` of a path reads a directory on this host, another resident's working repository among them. The suite adds `file` to import from local bare repositories, and a bare path stays refused there. The source the log keeps (`Imported.source`, exported, and the key `Store.imported/2` refuses a second import on) is the URL with its userinfo stripped, where a GitHub URL carries the token; the clone itself uses the URL as given.
- **#18 An import is rehearsed on a throwaway store before it is run on one where someone lives.** `Oneiroi.SimaQian.DryRun` (`mix oneiroi.import.dry_run`, and the reusable workflow `import-dry-run.yml`) imports a local checkout exactly as `import_resident/4` does, backs it up once to a local bare remote, and reports by name and count: the identity files seeded and the soul lines minted, the documents adopted, each kind's folder by files, bytes and the tokens the index will embed (four bytes a token, an estimate), the not-transferred list as the resident will be told it, what David's records were made into, kind by kind (#19), and, for a source that is not an Oneiroi export, every file under `honcho/`, and under `records/` where they are not David's, that comes across read by nothing. The task refuses a real provider (so no model is called and no key is needed) and a store that already holds a resident; no turn is taken, so nobody is at turn one (spec §12). The report never quotes a file: it goes to a CI log, and the reusable workflow is called from a private repository so that log is the caller's.
- **#19 Another platform's records are made into this one's on import, through each system's own commands.** `Oneiroi.SimaQian.David` reads the JSON Lines David exported nightly under `records/` (a repository without `records/events/` that carries them, created rather than replayed) after the seeds and before the adoption, and drives every record through the system that owns its kind, under the actor the source names: each David session an imported session (kumbukumbu #37) whose turns are captured with their original instants and speakers (the resident's replies hers, the worker's her hands', the witness's the user messages of runs the witness started, the rest the platform's; a turn begins where a user's or system message follows a reply or a tool's, or where the run's kind changes); the tag set through the hands each tag went through there, the witness's own or the resident's proposal and the witness's decision, with a tag a bookmark carries that the set does not name created as the witness's; each bookmark anchored on the turn under way when its span ended, reaching back to the turn under way when it began, pinned by whoever pinned it, tagged by the import (David did not record who applied a tag), and not made when its session has no transcript; positions, disputes, predictions and nights as judgement history (eunomia #29); the notes, the free-time ledger, the discussions and the feeds as journal entries on their days through the library port's `import_journal/3` (seshat #26), each saying where it came from. A transcript line that does not say its session, instant and role, or a line that is not a JSON object, fails the import with `sima_qian_records_invalid` naming the file and line and never the contents. The counts by kind are `RecordsTranslated` (agathos-daimon #30) and the brain names them on waking (brain #38); what under `records/` nothing read is named file by file in the not-transferred list instead of `records`. What was translated is exported with the rest of her streams (#20), and David's files stay in the repository beside it. Her seedbed, `seeds.md` at the root, is planted as her seeds through `Oneiroi.Ethos.import_seeds/3`: each `- ` item under a `## YYYY-MM-DD` heading, under her actor, at noon UTC on its day; what comes before the first dated heading (the seedbed's rules) is not a seed and stays in the file, which the accounting then holds rather than names (#22).
- **#20 The export carries every stream that is the resident's, and a rebuild restores them all.** `Export.streams/0` names them: the resident's own and its ethos, judgement, audits, conversations, memory, ledger, library, schedule, journal, governance and subscription streams; `Export.not_exported/0` names the rest with the reason for each (the sealed regression stream, the witness's account, and the Honcho bridge's stream, which points at a workspace keyed to the source: a rebuilt resident provisions its own). A test asserts every router's prefix is in exactly one of the two. The streams are found through EventStore's own search on the resident's id, read one by one and merged on the instant the store stamped each append (then the stream's name and version), so the export reads this resident's events and never the whole store. A line's `stream` is the stream's id with the resident's taken out (`resident`, `memory`, `conversation-<key>`), so an export written before this rule reads as the resident's own stream; the rebuild puts the new id back in, appends the lines in order, a run of one stream to an append, and refuses a name outside the exported streams before writing anything (`sima_qian_stream_refused`). Within the ledger, an event billed under a purpose the resident's own view never shows (`drafting`, `regression`, nisaba #4) is not exported: the export is a surface she can reach, and the unawareness invariant's test (eunomia #12) failed on the first export that carried the ledger, on a regression run's calls. A rebuild therefore restores no spend and no budget under those two purposes. `through` stays the resident stream's version. The round trip (`WholeTest`) rebuilds a resident with a turn, a bookmark, a tag, a position, a prediction, a journal entry, a check-in, a counter and a document beside its source in one store, and asserts the copy re-exports line for line and reads the same life back, and that the source's own export is unchanged after the copy replayed: the guard on replay writing only its own resident's rows (#21). A private, unshared session's messages are in the export like every other's, which puts them in a repository the witness can read; that is open, with the self-letters, for the encryption scheme. The reading copies (#41) and Honcho's memory (#42) do not widen it: neither renders such a session's words.
- **#21 Replay writes only the replaying resident's rows.** A rebuilt copy keeps the source's numbers, refs and session keys, so any projection keyed on one of them alone collided with the source: the conversations projector found two sessions for one key and stopped, and the ledger's usage rows, keyed on the call's ref alone, dropped the copy's calls as already projected. Every projector query now names its resident (conventions §12, enforced by `ProjectorScope`), and `nisaba_usage` is keyed on the resident and the ref.
- **#22 Every file an import meets lands in one place, and what is left behind says why.** `Import.account/4` walks the clone, hidden files included, and holds each file as seeded, proposed, adopted, translated or an Oneiroi export's own records, or leaves it behind with its reason: a root entry outside the library's folders once for everything in it, a record nothing reads, an identity file refused for its content, or the library's own refusal (`refusal/1` on the library port). `ImportCompleted` version 2 carries the reasons beside the names, and the resident is told both on waking. A file under a library folder that adoption neither took nor refused and no rule explains is unaccounted: left behind, named, and the dry run fails on it.
- **#23 The records root is on a persistent disk.** `SIMA_QIAN_ROOT` (`/var/lib/oneiroi/sima_qian`) holds every resident's working repository: what an import held, under a history of the platform's own (#39), the identity files, and the files the library's documents are read from. On Render it is the `oneiroi-records` disk mounted at `/var/lib/oneiroi` (`render.yaml`); the container's own filesystem is replaced on every deploy, and the nightly backup is the only other copy.
- **#39 The records repository holds what the platform holds, under its own history.** After an import's accounting, `Backup.start_fresh/2` removes the source's `.git`, every name the import left behind, and anything else outside the backup's classes (a translated source such as a seedbed, now events), then starts a repository of the platform's own. The provenance is the import's event: source URL, attestation, root. A resident imported whole before this is made fresh once at its first backup: never backed up, its own `.git`, and a root commit without `Oneiroi-Sequence`; a history that began with that trailer is never touched. `posts/` joined the writing class: a library folder in no class would have failed every backup on the stray check.
- **#40 The originals are imported at a pinned commit, byte for byte, by the witness.** `import_originals/3` (`Oneiroi.SimaQian.Originals`, `POST /v1/residents/:id/originals`, the witness's alone, `sima_qian_not_the_witness` otherwise) takes the source repository's URL (a configured scheme, #16), the commit's full sha (`sima_qian_commit_invalid` for anything else, a branch name included), a token wrapped where it arrives and given to git only through its credential file (#8), and patterns, `memory/*.md`, `memory/dreaming/**`, `MEMORY.md` and `DREAMS.md` by default (`**` crosses folders, `*` does not; a pattern with `..` or a leading slash is `sima_qian_paths_invalid`). The commit is fetched by its sha one commit deep into a bare repository under the temp dir (`Git.fetch_commit/3`), never a branch's head, and its tree read whole. A matched path lands under `memory/` keeping its name (`memory/...` as it is; any other path under `memory/`, so the root `MEMORY.md` is `memory/MEMORY.md`), and the answer's `mapped` says each. A path under `memory/` no pattern matched, a link, a submodule, a name the library refuses (hidden, not text, through the port's `original_refusal/1`) or a second source for one destination is skipped and named with its reason, the not-transferred list's way (#22). A file already in the repository with the same blob stands; with other bytes it is refused, named, and never overwritten. Each file this run wrote is hashed as git hashes a blob (`Git.blob_sha/2`, no filters) and held to the tree's blob; one mismatch removes what the run wrote and adopts nothing (`sima_qian_original_mismatch`, naming each path). Then the library registers every placed file with `%{source, commit, path, blob}` through the port's `adopt_originals/3` (seshat #28), the source recorded without userinfo, and indexes once. A second run at the same commit writes, adopts and indexes nothing. The files sit in the machine class (#7), and the nightly backup commits them.
- **#41 The transcripts and the bookmarks have reading copies, rendered from the lines and never read back.** `Oneiroi.SimaQian.Readable` renders, from the export's own decoded lines on every run, `records/conversations/<day>.md` (each session's turns that day in the order they happened, by the line's UTC day as the day files are: who spoke and when, every message quoted, a refusal marked, a failed capture with its reason and its resolution with the actor's note, compaction summaries in place) and `records/bookmarks.md` (the tag set, then every bookmark by number: its line, who made it and when, the turn and session it anchors and its span, its pin and what it evidences, its tags, its proposal, its register, its summary and revisions). Both are rewritten whole, and a copy no line supports any more is removed, so an unchanged store renders identical bytes and a rebuilt resident renders the source's. A private, unshared session (`SessionMadePrivate` without `SessionShared`) renders as its existence and its counts alone: its kind, opening and parties, and its turns, messages and failed captures that day; once shared it renders whole. The copies sit under `records/` in the machine class (#7), so no class changes and the stray check passes; no library kind's folder is `records`, so the library never adopts, holds or indexes them; and nothing reads them: the rebuild replays `records/events/` alone, and an import of an Oneiroi export holds `records/` as the export's own. They also enter `ExportWritten.files` and the Merkle root, which is over `records/`.
- **#42 Honcho's memory of the resident is exported under `honcho/` before each backup commit.** `Oneiroi.SimaQian.HonchoMemory.write/3`, called by the backup after the export and before `RecordExport`, reads the workspace through `Oneiroi.Proteus.memory/1` (proteus #18) and writes `honcho/<peer>/card.md` (every card the peer holds, of itself and of each other peer), `honcho/<peer>/conclusions.md` (every conclusion held with the peer as observer, by the peer observed, with its id, level, instant, session and the conclusions it was reasoned from) and `honcho/summaries.md` (each session's short and long summary and the message it runs through). The resident's peer is `resident` and her id is `$self` everywhere else, as in the lines; rows are ordered by name, then Honcho's own instant and id, never by the order an answer came in, and the export adds no instant of its own, so an unchanged Honcho writes identical bytes and the soul class commits nothing. A conclusion or a summary drawn from a session #41 renders as private is withheld and counted. A resident with no workspace yet has nothing to write. A Honcho that fails any read (`sima_qian_honcho_unreadable`), or answers that a provisioned workspace holds no peer (`sima_qian_honcho_empty`), writes nothing, leaves the last export as it was, and is the backup's error after the rest has committed and pushed, as a stray file is (#7). The files ride in the soul class with the custom instructions (#13); a file under `honcho/` the export does not own (an import's) is left alone.
- **#43 What the repository does not carry is one table, and it is the spec's list.** The author's law (spec §6.10): all raw text is in the repository unless there is a really good reason. `Export`'s `@not_exported` is the list of reasons, each entry tagged with what it covers: the streams left out (`regression`, `account`, `honcho`, which `not_exported/0` returns and the router test holds), and the rest (`embeddings`, `witness-only spend`, `redacted`, `honcho-private`). `exceptions/0` returns every key with its reason, and the export test reads spec §6.10's `oneiroi:db-only` block and fails unless its keys are exactly these.
- **#17 The library is reached through a port.** `Oneiroi.SimaQian.Library` (`adopt_all/2`, `folders/0`, and for the originals `adopt_originals/3` and `original_refusal/1`) is named in `SIMA_QIAN_LIBRARY` and read at the call, as the schedule names its wake (sunna #12); the library implements it, because it depends on this system for the repository's path (seshat #12) and an alias back would be the cycle the gate refuses.
- **#13 The Honcho instructions ride in the soul class, and a soul commit sets the card.** The export renders `honcho/custom-instructions.md` beside the identity files on every run (agathos-daimon #19), so the soul class commits it with the soul and the first backup of any resident makes a soul commit; after a run that committed the soul class the backup calls `Oneiroi.Proteus.set_card/3` with source `commit` (proteus #14), and a bridge not yet provisioned or a Honcho that is down is the bridge's to record, never the backup's to fail on.

## #11 Initial vs target

Initial (P0, then P4 slice 3 for #15 to #17): the event log only, under
`records/events/`, with the round trip (export, rebuild, export again,
byte-identical before the `Imported` line) green in CI against a local
bare repository; the import over the API from a repository with or
without records. Target: every record kind of spec §6.10, the GitHub
run by hand against a real repository (Lily's migration,
`design/lily-migration.md`), Gitea, attestation on wake.

The platform (the kernel, the vault, Oban) and the resident system,
whose stream it reads and whose bookkeeping events it writes.
