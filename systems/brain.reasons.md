# brain: reasons

## #3
Spec §5 and F12: context assembly is recorded so that "drew on N
things" is introspection productized; an estimate that says it is one
beats a count nobody took.

## #4
Spec §5: a refusal shown as a defect state is censorship by styling, and
a budget stop told anywhere but the transcript is told to one party.

## #5
Two captures interleaving on one session would put the second user
message before the first reply in the record both parties read.

## #6
Measured while building it: `Phoenix.Socket.Transport` fetches the
session only with a `_csrf_token` param that validates against a token
`Plug.CSRFProtection` put in the session, and this app has no such
plug (systems/gaia.md #5). A token the client fetches over the
Origin-checked API is the same proof, five minutes long.

## #7
A pin that does not exist yet cannot be read; a setting with a stated
placeholder is replaced by the pin in the regression slice.

## #10
Spec §5: "Tools are the same core functions the MCP server exposes,
chosen by role; it never gets steward operations." Capturing the calls
is spec §6.3's full capture: a transcript showing a reply that "just
knew" something the resident looked up is a transcript with a hole. A
turn that dies on a misnamed tool loses the reply the steward is waiting
for; the model reads the error and tries again or answers without it.

## #11
Spec §5: "a memory flush before it (the resident writes what it wants to
keep), a summary that never deletes history", the knobs the OpenClaw
audit named, re-owned. The threshold is a guess, said so in its usage
line; the honest measurement is a model's context against real
sessions, which no one here has taken.

## #12
Spec §5: "stable prefix first for prompt caching (soul files, AGENTS,
the pinned bookmark lines)". First contact is "the first captured turn
in a session that is not a regression session" (spec §6.2) and the turn
is where a capture is known to have landed.

## #13
Spec §6.3: "Whether to enact is thinking, done by the brain with those
turns in front of it"; "the brain self-tags at turn time
(`behaviour_enact`), which is cheap and in character."

## #14
Spec §6.2: "every authored field offers 'write it with me' (a draft
from a prompt, billed under the `drafting` purpose)". Returned rather
than written so the origin on the seed is the steward's statement, not
the model's.

## #15
Spec §6.4: "as an honestly told model change after" first contact;
spec §5: the notice lands in the transcript, where both parties read
it in the same place.

## #16
Spec §6.4: "the brain is given the seed files and nothing of the run's
purpose." The index would carry the resident's memory into a session
that is never captured, and the formation line names a date the run
has no business knowing.


## #17
Spec §5: "sessions opened by wake (a check-in lands in main)" and §8:
"wake text never carries the words." The note is the core's, so it is
a system message by the platform and not a user message by anyone; the
purpose is the caller's because the ledger bills free time on its own
line (spec §6.11).

## #18
Spec §8: "the tool set is the role's: brain gets everything the
resident has (... position_*, dispute_check, prediction_* ...)".

## #19
Spec §5 lists Honcho's context in the assembly order; conventions §8
makes an external's failure retryable and not the caller's.
